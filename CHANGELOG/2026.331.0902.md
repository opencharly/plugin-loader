# 2026.331.0902 — feat(plugin-loader)!: follow the spec module's Android removal

## Summary

The spec module's Android retirement (spec `v0.2026331.808`) removed `AndroidSpec`, `ResolvedAndroid` and the `kind:android` substrate; sdk `v0.2026331.837` removed `loaderkit.ValidateAndroidDevices`. This repo's `candy/plugin-loader` provider still implemented the Android seam, so the module did not compile against the new contract:

```
$ cd candy/plugin-loader && go build ./...
./plugin.go:332:107: undefined: spec.ResolvedAndroid
./plugin.go:333:19: undefined: loaderkit.ValidateAndroidDevices
```

This change deletes the Android surface the plugin owned:

- the provider's `ValidateAndroidDevices` `spec.ProjectLoader` seam (the interface no longer declares it);
- `android_loader_test.go` (`TestValidateCheckBeds_Android`, Android-bed validation only);
- `cue_entity_xor_test.go` (`TestAndroidDeviceXOR`, Android-device XOR only);
- the `android` row in the shared `spec.Threaded` test fixture.

The generic substrate set (pod / vm / local / kubernetes / kubevirt / kindcluster / firecracker) is unchanged. `rawTemplateMap` was defined in the deleted Android test file but is still used by the vm/local fixtures in `check_bed_run_test.go`, so it moved to the shared test helper (`threaded_test_helper_test.go`) rather than being deleted.

Dependencies pinned to the merged prerequisites: spec `v0.2026331.808`, sdk `v0.2026331.837`.

### Spike

The cause is a removed contract identifier, so the spec/sdk artifacts settle the candidates:

- **A — delete the Android seam and its tests (winner).** The new spec declares no replacement for `AndroidSpec` / `ResolvedAndroid`, and the new sdk declares no `ValidateAndroidDevices`; the surviving generic loader ops remain. Deleting the seam and the two Android-only tests gives a green `go build` / `go test`, and the vm/local fixtures still compile because `rawTemplateMap` is re-homed. The absence is measured against the module source:

- **B — rewrite the seam against a surviving loader op.** Not plausible: no surviving op validates Android devices (the grep above), so a rewrite would invent a contract the modules do not declare.

The diff implements A.

**Live-execution boundary.** The deleted `ValidateAndroidDevices` seam no longer exists, so it cannot execute under a live process; the prebuilt `charly` binary used for `charly box validate` bakes the previous plugin-loader and cannot exercise this diff. That `box validate` run is a STRUCTURAL check of this repo's candy/plugin entity only. The real gate for the changed code is the module gate: `go build ./...` proves the removed `spec.ProjectLoader` seam and its `spec.ResolvedAndroid` / `loaderkit.ValidateAndroidDevices` references are gone, and `go test -count=1 ./...` runs the surviving loader tests (parse, walk, check-bed validation).

# 2026.254.2014 — feat(loader): carry the override-precedence seam — RepoOverrideDir delegates to loaderkit

## Summary

Wave step 2 of 3 of the override-precedence seam NAMED in charly #587's merged body: `candy/plugin-loader` implements `spec.ProjectLoader.RepoOverrideDir(repoPath string) (string, bool, error)` as a one-line transit to `loaderkit.RepoOverrideDir`.

**Why the seam exists.** charly #587 made the served-plugin-artifact report honest but had to record a named follow-up instead of the wanted behavior: a `CHARLY_REPO_OVERRIDE` local tree cannot outrank the BAKED plugin probe in charly core, because core may not reach the parser itself — `charly/import_purity_test.go` forbids every `github.com/opencharly/sdk` import in core, and the parse lives in the sdk (sdk #251, tag `v0.2026254.1740`: `loaderkit.RepoOverrideDir(repoPath, envValue)`). Step 1 (spec #130, tag `v0.2026254.1930`) declared the method; **this PR** carries it to the plugin; step 3 makes `charly/plugin_loader.go` call `requireProjectLoader().RepoOverrideDir(...)` before the baked-artifact probe.

**The delegator** (full doc comment in the diff):

```go
func (*provider) RepoOverrideDir(repoPath string) (string, bool, error) {
	return loaderkit.RepoOverrideDir(repoPath, os.Getenv(proc.RepoOverrideEnv))
}
```

The env value is read **implementation-side** — the loader plugin owns the env plumbing and `spec/proc.RepoOverrideEnv` names the variable — which is exactly why the seam carries ONLY `repoPath` (R3: a consumer cannot thread its own env read in and re-derive the parse).

**The pin bump lands in the SAME commit, deliberately.** The candy pins `github.com/opencharly/spec v0.2026254.1930` (was `v0.2026251.500`) and `github.com/opencharly/sdk v0.2026254.1740` (was `v0.2026251.531`). `f2_seam_test.go` asserts `var _ spec.ProjectLoader = (*provider)(nil)`, so the new interface method and its delegator must appear together or the package stops compiling — proven by the negative control below.

**No manifest / wire / generated change**: a typed compiled-in seam (like `EnsureRepoDownloaded`), reached in-proc by core through the seam it already resolves — no envelope, no generated artifact.

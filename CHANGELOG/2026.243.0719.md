# 2026.243.0719 — refactor(loader): cut the version-arbiter test over to the advisory sink

## Summary

`loaderkit.PickCandyVersion` now takes a **required** advisory sink instead of writing to
stderr (opencharly/sdk#200). This repo is its one external consumer, and is cut over in the
same sweep so no compatibility shim has to exist at any point.

The diff is confined to this repo's version-arbiter test plus the dependency bump:

```
candy/plugin-loader/go.mod                     |  2 +-
candy/plugin-loader/go.sum                     | 12 ++++------
candy/plugin-loader/pick_candy_version_test.go | 33 +++++++++++++-------------
3 files changed, 21 insertions(+), 26 deletions(-)
```

### The stderr scraping is deleted, not kept

The test used to redirect `os.Stderr` and read the bytes back to assert on the advisory:

```go
capture := func(fn func() spec.CandyCandidate) (spec.CandyCandidate, string) {
	old := os.Stderr
	r, w, _ := os.Pipe()
	os.Stderr = w
	got := fn()
	…
	return got, buf.String()
}
```

That was a workaround for an advisory with nowhere structured to go. With the sink it becomes
a plain collector, and `bytes`, `io` and `os` leave the imports with it — **26 deletions
against 21 insertions**, so the change removes more than it adds.

Both original assertions are unchanged in meaning: identical per-entity versions must produce
NO advisory (the re-tag regression guard), and differing versions must warn exactly once with
the newest winning.

## How tested

```
$ go test ./...

```

Run on the committed tree against the published `sdk v0.2026243.714` — no `replace`. The
compile is itself the proof the tag carries the cutover: this test calls `PickCandyVersion`
with three arguments, which does not compile against the old two-argument form.

This is the test that would have broken had the sdk change shipped a shim instead: it is the
reason the shim was considered, and cutting it over here is what let the shim be deleted.
